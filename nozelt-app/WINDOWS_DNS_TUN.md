# Windows DNS и TUN — 1.0.0+34

В «Настройки → Сеть» добавлены отдельные страницы DNS и TUN. Изменения в форме являются черновиком до «Сохранить». Существующие настройки, серверы, профили маршрутизации и порядок правил сохраняются. Android продолжает использовать VpnService, свой стек и прежний DNS; расширенные Windows-параметры на Android не применяются.

## DNS

- Fake-IP или Redir-Host; IPv4-пул в пределах 198.18.0.0/15, IPv6-пул ULA, TTL синтетического ответа.
- Фильтр Fake-IP: исключения (blacklist), включения (whitelist), последовательные правила (rule). Поддерживаются домены, маски и GeoSite. В режиме правил последняя строка должна явно задавать MATCH,fake-ip или MATCH,real-ip.
- Основные серверы, отдельный DNS для VPN-сервера, отдельный DNS направлений DIRECT.
- DNS по доменам/GeoSite и отдельные политики для имён VPN-серверов.
- Резервные серверы, отложенный запрос, проверка страны ответа, фильтры IP-подсетей и доменов. Резервный DNS по умолчанию выключен; страна RU не включает его автоматически.
- Ответы AAAA, время ожидания IPv6, предпочтение HTTP/3 для DoH.
- Кэш LRU/ARC, размер кэша, сохранение Fake-IP между запусками по явному выбору пользователя.
- Собственные записи hosts и использование системного hosts Windows.

Пример серверов — по одному в строке:

```text
https://1.1.1.1/dns-query
https://9.9.9.9/dns-query
```

Пример политики:

```text
+.example.com = https://9.9.9.9/dns-query
geosite:google = https://1.1.1.1/dns-query
```

Пример фильтра в режиме «Правила по порядку»:

```text
DOMAIN-SUFFIX,example.com,real-ip
GEOSITE,google,fake-ip
MATCH,fake-ip
```

Пример hosts:

```text
nas.lan = 192.168.1.10
example.test = 192.0.2.10, 2001:db8::10
```

Real-IP в фильтре DNS означает настоящий адрес назначения вместо синтетического, а не разрешение обойти VPN. Выход по-прежнему выбирают правила маршрутизации.

### Границы защиты DNS

Все удалённые резолверы задаются через DoH/DoT/DoQ с IP-адресом. Системный DNS, открытый UDP/TCP DNS, параметры ECS, отключение проверки сертификата и ручные суффиксы выбора интерфейса запрещены. Основные, резервные, DIRECT-резолверы и доменные политики получают принудительный `#PROXY`; пользователь не может заменить его на DIRECT.

Отдельный шифрованный bootstrap нужен для разрешения имени VPN-сервера до появления соединения. Он идёт по физическому интерфейсу: это необходимое исключение для установления VPN, а не запасной путь для DNS сайтов. Если bootstrap пуст, используются выбранные основные серверы. Xray требует HTTPS-резолвер; DoT/DoQ не подменяются произвольным DNS.

Политики имён VPN-серверов также передаются нативным транспортам: их домены сопоставляются тем же парсером доменов/GeoSite, затем Xray получает отдельные DNS-записи, а sing-box — отдельный domain_resolver. Для собственного endpoint DNS sing-box выбирает первый сервер политики (ограничение используемого контракта native bootstrap); резервирование DNS сайтов остаётся в общем Mihomo frontend. Это не означает проверенную отказоустойчивость всех bootstrap-резолверов sing-box.

Локальные и обратные имена .lan/.local/localhost/in-addr.arpa/ip6.arpa получают локальный пустой ответ. Для известных LAN-узлов можно использовать hosts. Произвольные RULE-SET из конкретного VPN-профиля в глобальных настройках DNS не поддерживаются; используются независимые от выбранного профиля домены и GeoSite.

DNS-listener на локальном порту не создаётся: TUN передаёт перехваченные UDP/TCP-запросы непосредственно встроенному резолверу. При prefer-H3 параметр respect-rules отключается согласно рекомендациям Mihomo; принудительный маршрут DNS через PROXY сохраняется.

Сохранение Fake-IP выключено по умолчанию. При включении домены и соответствия IP записываются без шифрования в `portable-data/core/cache.db`; это прямо указано в интерфейсе. Выключение прекращает использование дисковых соответствий, но не удаляет ранее созданный файл. Другие данные профилей и настроек остаются защищены DPAPI.

## TUN

- gVisor, System, Mixed и MIPS. Mixed: TCP через System, UDP через gVisor. Прежний gVisor остаётся значением по умолчанию.
- MTU 1280–9000; IPv6 и адрес IPv6-интерфейса.
- Таймаут UDP 30–86400 секунд; таймаут ICMP 1–600 секунд; запрет пересылки ICMP.
- Для MIPS: CUBIC, Reno, BBR и BBR3.
- Частные loopback-адреса TUN для программ, работающих с локальным прокси.
- Отдельная вкладка показывает обязательные параметры защиты: захват маршрутов, автоматический выбор внешнего интерфейса, strict-route, перехват TCP/UDP DNS, WFP kill-switch и имя адаптера Nozelt.

Обязательные параметры нельзя отключить из формы. OS-исключения маршрутов конфликтуют с полным захватом и WFP; исключения DIRECT задаются в «Маршрутизация», сохраняя приоритеты процессов/доменов/IP. Linux-only auto-redirect/GSO/UID/interface-фильтры не показываются. Endpoint-independent NAT не добавлен: в комплектном sing-tun v0.4.27 поле объявлено, но стек его не использует. Показывать его как рабочий переключатель было бы неверно.

## Применение и проверка

До записи проверяются размеры, адреса, типы резолверов, диапазоны, фильтры и политики. При выбранном VPN-профиле Windows дополнительно проверяет кандидат нативными парсерами, даже при выключенном VPN. Проверка не применяет TUN или WFP. При активном соединении используется существующая последовательная защищённая замена с откатом настроек и восстановления предыдущего соединения при ошибке.

Проверки этой версии:

- Flutter analyze и полный набор Flutter-тестов, включая сохранение старых настроек, отклонение опасных DNS и предварительную нативную проверку до записи.
- Скриншоты всех вкладок DNS/TUN при 720×520 и 1180×760, русский/английский, увеличенный текст; повторная проверка остальных экранов и Android-эталонов.
- Go-тесты и race detector для ядра, Windows runtime и схемы WFP.
- Настоящие DNS-пакеты по UDP/TCP через случайные loopback-порты: Fake-IP, обратное соответствие, стабильность адреса, TTL, IPv6, blacklist/whitelist/rule, Redir-Host, политики, fallback, LRU/ARC и очистка памяти кэша. Публичный DNS и системные маршруты не используются.
- Сохранение IPv4/IPv6 Fake-IP проверяется между отдельными процессами в временном каталоге и при последующем отключении сохранения.
- 144 комбинации: три ядра × четыре стека × два режима DNS × два значения IPv6 × три режима фильтра; парсинг реальными комплектными ядрами без запуска TUN. Дополнительно прежние проверки маршрутизации/профилей.
- Тесты MIPS на адаптере в памяти: TCP, UDP, ICMP, loopback, заполненное кольцо Windows, завершение стека. Это не проверка физического сетевого адаптера.

Koala Clash TUN на рабочем ПК не отключался. Полный системный прогон Wintun/WFP, аварийного обрыва, смены физической сети и перехват пакетов на внешнем адаптере не выполнены: для них требуется отдельная Windows VM или отдельный согласованный сеанс без конкурирующего TUN. Успешные локальные проверки не доказывают отсутствие всех сетевых утечек.
