# Nozelt Windows portable — первая версия, 2026-10-03

Основа: интерфейс, профили, настройки и маршрутизация Android 1.0.0+33.
Windows x64, Windows 10/11. Распакуйте весь архив в доступную для записи папку
и запустите `nozelt.exe`. Для Wintun требуется запуск с правами администратора.
Visual C++ runtime, Wintun и все три ядра входят в архив; отдельный установщик не нужен.

Актуальная техническая итерация 06.10.2026 описана в
[WINDOWS_SECURITY_AUDIT.md](WINDOWS_SECURITY_AUDIT.md): постоянная WFP-защита,
DNS, provider routing, восстановление, обновления зависимостей и точные пределы
проверок. Новую системную политику следует испытывать в отдельной VM;
работающий Koala Clash на этом ПК не изменялся.

## Реализовано

- Левая панель: Главная, Прокси, Маршрутизация, Подключения, Логи, Настройки.
  Снизу — синхронизированный переключатель Правила/Глобально.
- Профили и подписки, выбор сервера и ядра, задержка, импорт из файла/буфера обмена.
- Общие с Android профили маршрутизации, экспорт/импорт конфигураций и ссылок.
  Категория «Процессы Windows»: имена вроде `steam.exe`, по одному на строку,
  с действиями Прокси, Напрямую, Блокировать. Отдельного Android-пикера здесь нет.
  Обе платформы сохраняют весь общий документ; при построении конфигурации
  Android исключает Windows-процессы, Windows исключает Android-пакеты.
  В режиме Глобально индивидуальные правила не применяются.
- Подключения: группировка по программе, счётчики отправленного/полученного трафика
  текущих активных соединений; поиск, адрес, протокол, правило и цепочка маршрута,
  просмотр и закрытие отдельных соединений либо всех сразу.
- Закрытие окна оставляет приложение и VPN в трее. Левая кнопка настраивается:
  показать окно или включить/выключить TUN. Ч/б иконка при отключении, цветная при включении.
  ПКМ: показать окно, включить/выключить TUN, Правила/Глобально, перезапустить, выйти.
- Автозапуск при входе в Windows, тихий запуск в трее, автоподключение
  к последнему выбранному серверу. По умолчанию автозапуск и автоподключение отключены.
  Явное отключение VPN не отменяется при следующем показе окна.
- Контроль состояния и восстановление работают и при скрытом окне.

## Ядра и устройство Windows VPN

В этой сборке: Mihomo **1.19.32**, Xray **26.9.30**, sing-box **1.14.2**;
Wintun **0.14.1**. Проверены официальные релизы на дату сборки. Для Mihomo и
sing-box выбраны стабильные релизы; Xray публикует этот релиз как pre-release.

Общий Windows TUN, DNS, правила процессов и телеметрия находятся в
`nozelt_core.dll` (Mihomo с gVisor). Для профиля Xray/sing-box трафик прокси
проходит через соответствующий отдельный процесс и локальный SOCKS5 с
одноразовым паролем. Сокеты внешнего транспорта привязаны к физическому интерфейсу,
чтобы не возвращаться в собственный TUN. Сохраняются нативные outbound-параметры
и используемые балансировщики провайдера.

Дочерние процессы находятся в Job Object с завершением при закрытии хоста.
Их готовность проверяется SOCKS-аутентификацией до создания TUN.
При смене физического интерфейса или падении внешнего транспорта запускается
его восстановление; общий TUN сохраняется. Редактирование только правил и режима
использует горячее обновление общего слоя. Смена сервера/ядра может потребовать
пересоздания соединений. Гарантия сохранения всех TCP-сеансов при смене сети не заявляется.

## Данные и автозапуск

Состояние находится в `portable-data` рядом с exe и не зависит от рабочей папки.
Профили и чувствительные настройки зашифрованы Windows DPAPI и привязаны к
пользователю/компьютеру. Для переноса на другой ПК экспортируйте профили и правила.
Старое состояние из APPDATA автоматически не импортируется.
Свежий архив не содержит локальных профилей, ключей или настроек сборочной машины.

Автозапуск создаётся только переключателем в настройках: задача Планировщика
`Nozelt-Portable-<SID>` для текущего пользователя с повышенными правами,
без сохранения пароля. Тихий запуск передаёт `--startup --silent`.
При перемещении portable-папки выключите и снова включите автозапуск, чтобы
обновить путь в задаче. Перед удалением папки отключите автозапуск.

## Воспроизводимая сборка

Нужны Flutter, Visual Studio Build Tools (C++/Windows SDK), Go и MinGW-w64.
Из папки `nozelt-app`:

```powershell
.\scripts\build_windows_portable.ps1
```

Скрипт собирает sing-box и официальный исходный архив Xray указанной версии,
проверяет SHA256 архива Wintun, выполняет Go-тесты с gVisor, строит DLL,
запускает `flutter analyze`, `flutter test`, собирает Windows release и
добавляет app-local Visual C++ runtime. Все версии зафиксированы в исходниках.
`-SkipCore` использует уже собранные ядра; `-SkipTests` пропускает проверки.

Результат сборки — candidate `build/portable/Nozelt/nozelt.exe` со статической
проверкой Defender. Готовый ZIP создаётся только после наблюдения запущенного
candidate сценарием `test_windows_release.ps1` и отдельной публикации через
`publish_windows_portable.ps1`. Процедура и ограничения описаны в
[WINDOWS_DEFENDER.md](WINDOWS_DEFENDER.md). Проверка без запуска больше не
считается достаточным основанием для выпуска.

Дополнительная проверка 18 конфигураций всех трёх ядер без TUN:

```powershell
$env:NOZELT_NATIVE_CORE_DIR = (Resolve-Path ..\native-cores\build\windows).Path
$env:NOZELT_DATA_DIR = "$PWD\build\validation-data"
New-Item -ItemType Directory -Force "$env:NOZELT_DATA_DIR\core" | Out-Null
Copy-Item android\app\src\main\assets\xray\*.dat "$env:NOZELT_DATA_DIR\core"
Copy-Item android\app\src\main\assets\xray\*.dat $env:NOZELT_NATIVE_CORE_DIR
dart run tool/validate_windows_core_configs.dart
```

Локальная интеграционная проверка реальных дочерних ядер без VPN и изменения маршрутов:

```powershell
cd ..\nozelt-core
$env:NOZELT_NATIVE_CORE_DIR = (Resolve-Path ..\native-cores\build\windows).Path
go test -tags=with_gvisor ./windowsdll -run TestRelay -v
```

Проверены: Flutter-анализ без замечаний и 158 тестов, верстка 1180×760 и 720×520, общие ссылки,
фильтрация платформенных правил, восстановление транзакций, тихое автоподключение,
контроль в трее, отсутствие повторного автоподключения после ручного отключения,
DPAPI, синтаксис реальными обновлёнными ядрами и по три цикла запуска/остановки
Xray и sing-box с аутентифицированным локальным SOCKS, передачей 64 блоков
данных по установленному TCP-соединению в каждом цикле, проверкой содержимого
и без оставшихся процессов. TCP-получатель находится на этом же ПК;
эти проверки не используют удалённый VPN-сервер.

Текущая DNS-политика (06.10.2026): Windows Xray разрешает доменные адреса транспорта
встроенным DNS с `ForceIPv4`/`ForceIP`, без возврата к системным fake IP.
Запросы bootstrap DoH получают отдельный freedom-маршрут с привязкой к
физическому интерфейсу. DNS из подписки заменяется выбранными HTTPS-резолверами
Nozelt. Если выбраны только DoT/DoQ, требуется настроить поддерживаемый HTTPS
резолвер: произвольного fallback нет. В sing-box к физическому интерфейсу
привязан только bootstrap DNS; DNS назначений идёт через прокси. Указан явный
резолвер доменных адресов. Начальный выбор сети использует физический default route,
а не маршрут к 1.1.1.1 через уже работающий чужой TUN. При выключенном IPv6
не создаётся IPv6-адрес TUN. На Главной добавлена общая с Android карточка
задержки с кнопкой измерения и индикатором выполнения.

Дополнительная локальная диагностика выбранного native-профиля:
`tool/prepare_windows_transport_probe.dart <portable-data> <output.dpapi>`
подготавливает временный DPAPI-файл; Go-тест `TestRelaySelectedProfileHTTPS`
включается только переменной `NOZELT_RELAY_PROBE_DPAPI` с путём к этому файлу
и требует `NOZELT_NATIVE_CORE_DIR`. Он обращается к публичному HTTPS endpoint
через выбранный сервер, не устанавливая TUN и не изменяя маршруты.
На этом ПК проверены три запуска выбранного Xray-сервера с тремя запросами
HTTPS 204 в каждом через Ethernet. Полный системный TUN этим не проверен.

## Первый тест на этом ПК

Реальное подключение к серверу, переключение сетей, UAC, нажатия на настоящий
трей и вход в Windows с задачей автозапуска требуют отдельной проверки на этом ПК.
Сборочные проверки этого не доказывают.

1. Запуск из распакованной папки; добавить профиль, выбрать сервер и подключиться.
2. Проверить внешний IP, DNS, сайты, длительную передачу TCP и UDP/QUIC.
   Повторить для Mihomo, Xray и sing-box с подходящими профилями.
3. В режиме Правила проверить `steam.exe`/другой тестовый процесс:
   Прокси, Напрямую, Блокировать; сверить список подключений и счётчики.
4. Переключить режим на Главной, внизу панели и в меню трея; сверить состояние.
5. Закрыть окно, проверить цвет иконки, оба действия ЛКМ, меню ПКМ,
   восстановление окна, перезапуск и выход без оставшихся дочерних процессов.
6. Во время передачи данных временно отключить/включить сеть, сменить интерфейс,
   проверить восстановление, логи и отсутствие циклического трафика через TUN.
7. Проверить обычный и тихий автозапуск после нового входа в Windows,
   автоподключение последнего сервера и отключение соответствующих опций.

Статистика программ в этой версии относится к активным соединениям;
долгосрочный архив расхода трафика по программам не ведётся.
Android APK/AAR и содержимое телефона в ходе этой Windows-сборки не обновлялись.

Вторая Windows-итерация 04.10.2026: native-проверки задержки используют те же
защищённые bootstrap DNS и привязку к физической сети, что и подключение;
активный TUN не изменяется. На выбранном сервере проверена задержка 25 мс
при работающем Nozelt TUN, а также девять успешных HTTPS-запросов в трёх
отдельных диагностических транспортных процессах. PID действующего Nozelt
и его основного Xray сохранились. Неиспользуемые повторы бренда на Главной
и в блоке версий удалены, верхний бренд и переключатели увеличены.
Флаги Windows — локальные PNG Twemoji v17.0.3, лицензия CC BY 4.0 и атрибуция
находятся в `assets/licenses/Twemoji.txt`; источник https://github.com/jdecked/twemoji.
Логотипы Windows получают плотную обрезку поля SVG перед масштабированием.
Меню трея использует нативный Win32 popup и системную тёмную тему Windows,
включая DPI, выбранный режим и подменю; owner-draw удалён. Его реальные клики после установки
новой сборки ещё требуют проверки; сборка C++ проверена.

`scripts/update_windows_portable.ps1` — подготовленный сценарий обновления,
не запущенный во время работающего TUN. Он проверяет SHA256 payload и пути,
дожидается ручного «Выйти из приложения», сохраняет прежние файлы, обновляет
portable без изменения `portable-data`, запускает новый процесс с одноразовым
`NOZELT_CONNECT_ON_START=1` и проверяет появление TUN-адаптера. Флаг не меняет
постоянную настройку автоподключения и учитывается лишь при первом старте.
При ошибке копирования сценарий возвращает прежние файлы и открывает старую
версию; подключение тогда включается пользователем. Адаптер Up сам по себе
не доказывает передачу трафика. Полный перезапуск процесса текущей архитектуры
закрывает TUN: ядро находится в DLL этого же процесса. Закрытие/возврат окна
через трей сохраняет подключение; обновление EXE/DLL требует перезапуска.

Исходники ядер: https://github.com/MetaCubeX/mihomo/tree/v1.19.32,
https://github.com/XTLS/Xray-core/tree/v26.9.30,
https://github.com/SagerNet/sing-box/tree/v1.14.2.
Изменения обвязки находятся в соседних `nozelt-core` и `native-cores`.
Лицензии поставляемых ядер находятся в `data/licenses`.


Визуальная итерация Windows 04.10.2026: подробности, ограничения и проверки
в WINDOWS_UI_AUDIT.md. Проверено 71 визуальное состояние; 145 Flutter-тестов.
Строки программ уплотнены, добавлены нативные иконки процессов с фоновым
извлечением и ограниченным кэшем. Минимум окна — клиентская область 720×520.

Во второй итерации устранено исчезновение боковой навигации при изменении
ширины окна, убрано пояснение тихого запуска, надпись Nozelt увеличена до
32 px. Доработаны узкая Главная, поиск логов/GeoIP, длинные значения настроек
и адреса соединений. Проверены все шесть страниц при минимальном окне
и увеличенном тексте. Запущенная пользовательская копия не заменяется.

`scripts/update_windows_portable_auto.ps1` поддерживает `-CloseRunning`
для автоматического завершения старого процесса после проверки payload
и резервного копирования. `-ValidateOnly` проверяет файлы, не закрывая Nozelt.
Сценарий совместим с Windows PowerShell 5.1; журнал и статус сохраняются
рядом с ним. Повышение прав сопровождается видимым окном, ошибка UAC
записывается в статус. Обновление второй итерации выполнено 04.10.2026 в 21:14:
файлы заменены, TUN восстановлен, три HTTPS-проверки вернули 204. Полный
перезапуск на время прерывает TUN. Реальный откат после ошибки ещё не проверен.

Третья итерация: тёмные подсказки, исправленная заливка переключателя слева,
категории маршрутизации по две в ряд и компактные элементы управления,
акцентная кнопка добавления профиля справа, настройки в одной колонке.
Поиск подключений и группировка всегда находятся на одной строке одинаковой
высоты. User-Agent и лишние пояснения убраны из формы добавления Windows.

Defender повторно блокировал EXE второй итерации с именем
Trojan:Win32/Bearfoos.A!ml, хотя ручная проверка прежде прошла. Причина пока
не установлена; защита и исключения не менялись. Чистая ручная проверка
не гарантирует отсутствие дальнейших срабатываний.

Третья итерация установлена после обычной повторной release-сборки.
300 файлов установленной копии совпали с portable-пакетом; новый процесс
запущен, TUN Up, три HTTPS-проверки успешны (204). Папка сценария удалена,
поэтому результат подтверждён файлами и подключением, а не его журналом.
