# nozelt-core architecture

> Living document. Update on every significant code change. If something here
> contradicts the code, the code wins — and this file is wrong and must be
> fixed.

## 1. Overview

`nozelt-core` is a Go module that embeds the [mihomo](https://github.com/metacubex/mihomo)
proxy engine and exposes a deliberately small surface to the Android side of
the Nozelt VPN client. It is compiled with `gomobile bind` into a
`nozelt.aar` library, which the Kotlin layer links against and calls via the
generated JNI glue.

Windows uses a C FFI ABI in `windowsdll/`, built as `nozelt_core.dll`.
The common Mihomo/Wintun frontend handles DNS, original process routing and
telemetry; Xray/sing-box are contained SOCKS transport processes.
`networkguard/` owns the WFP policy in a dynamic session: Windows removes it
when the session closes or the process exits. A technical stop keeps it for at
most 30 s; a failed start, any disconnect, a crash or a kill releases it. The complete Windows lifecycle, recovery,
dependency overlays and verification limits are documented in
[WINDOWS_SECURITY_AUDIT.md](../nozelt-app/WINDOWS_SECURITY_AUDIT.md).
The flow below describes the Android path.

The module is consumed end-to-end like this:

```
Flutter UI ──MethodChannel──▶ Kotlin (Android)
                                  │
                                  ▼  JNI (gomobile-generated)
                              binding/  (Go, this module)
                                  │
                                  ▼
                              core/     (lifecycle, config, status, log forward)
                                  │
                                  ▼
                              mihomo    (Go dependency)
```

Mihomo is **really running** — not a stub. `Start` parses
YAML, hands it to `executor.ApplyConfig`, verifies the requested inbound
ports actually came up, subscribes to mihomo's log stream, and exposes live
traffic counters via the `tunnel/statistic` manager.

`parseConfig` also enforces host invariants after parsing: mihomo's
`profile.store-selected` and `profile.store-fake-ip` are always disabled.
No imported YAML can create the default shared-storage cache, delay Android
startup while it is opened, or persist fake-IP browsing metadata outside
Nozelt's private encrypted state.

`nozelt-core` also drives a real **TUN** interface for
device-wide routing. The TUN file descriptor is still created on the Kotlin
side (`android.net.VpnService` owns the OS-level VPN), but Kotlin hands the fd
to us via the new `SetTunFd` binding; `core` injects it into mihomo's config
so sing-tun serves the tunnel on that fd. So the split is: **Kotlin owns the
VpnService / route table / per-app rules; `nozelt-core` owns the packet
engine on the fd.** See §5a and §6a for the data flow and the fd-ownership
contract.

The current Android hardening adds a process-wide mihomo socket hook backed by
`VpnService.protect(fd)`, aggregate protection diagnostics, underlay recovery
that rebuilds trackers/proxy/DNS adapters without replacing the TUN fd, and a
resource watchdog that reacts before an FD retry storm kills the Flutter
process. The host keeps mihomo in rule mode, opens no local inbound ports, and
uses fake-IP DNS through encrypted upstreams.

Layering rule: only `core/` is allowed to import `github.com/metacubex/mihomo/*`.
`binding/` must not depend on mihomo directly — that keeps the gomobile ABI
decoupled from mihomo version bumps. `logger/` depends on nothing else in
this module so it can be imported from anywhere without cycles.

`tools.go` carries the `//go:build tools` tag — it is excluded from normal
`go build` / `go test` runs and only exists so `go mod tidy` keeps
`golang.org/x/mobile/bind` in the module graph (gomobile/gobind need it at
.aar generation time).

## 3. Public API (binding/binding.go)

Every export below is part of the `.aar` ABI consumed by Kotlin. Changing a
signature is a breaking change for every caller — prefer adding a new
function over changing an existing one.

| Function | Signature | Returns | Notes |
|---|---|---|---|
| `Start` | `Start(configYAML string) error` | nil or wrapped error | Idempotent within a process — returns `ErrAlreadyRunning` if called twice without `Stop`. Performs a real `executor.ApplyConfig`, exact port sanity checks, and (when the config enables TUN) rejects all parallel local/controller/DNS/server inbounds, injects the fd from `SetTunFd`, and verifies the TUN came up. |
| `Stop` | `Stop() error` | nil or wrapped error | Returns `ErrNotRunning` if engine is idle and has no retained restart mapper. Closes tracked connections, runs `executor.Shutdown` (TUN/fd), explicitly closes non-TUN listeners plus outbound adapters/provider tasks, clears DNS/fake-IP memory and global tunnel references. Also clears a mapper left by a failed technical replacement. A 10s timer warns but Stop remains a strict completion barrier. |
| `StopForRestart` | `StopForRestart() error` | nil or wrapped error | Same strict transport/listener teardown, but retains only the in-memory FakeDNS host mapper for the immediately following Android TUN/profile replacement. `Start` reuses it only when the synthetic IPv4/IPv6 ranges match. No DNS transport or credentials survive; final/user stop must use `Stop`. |
| `SetTunFd` | `SetTunFd(fd int) error` | nil or validation/lifecycle error | Records the detached duplicate of Android's TUN fd to hand to mihomo on the next `Start`. `0` clears it. An abandoned pending fd is closed before replacement, while a live sing-tun descriptor can never be overwritten. gomobile maps Go `int` → Java `long`, so the generated method is `setTunFd(long)`. See §6a for the ownership contract. |
| `SetSocketProtector` | `SetSocketProtector(p SocketProtector)` | — | Retains the Android callback and installs `dialer.DefaultSocketHook`. Every outbound transport dial fails if protection is absent/rejected. Pass nil only after Stop drains transports. |
| `ReloadConfig` | `ReloadConfig(configYAML string) error` | nil or wrapped error | Engine must be running. Calls `ApplyConfig` again with `force=true`; rules-only edits reuse live outbound adapters, while changed proxy definitions close the old adapters after apply. Failed candidates close only resources they own (borrowed live adapters remain open). Does not release the fd on failure. |
| `RecoverNetwork` | `RecoverNetwork() error` | nil or wrapped error | Re-parses the active config with the same TUN fd, closes trackers and old adapters, reapplies proxy/DNS state after an Android underlay change, then restores explicit selector choices. |
| `SelectProxy` | `SelectProxy(groupName, proxyName string) error` | nil or wrapped error | Updates a live mihomo `select` group and remembers the choice for subsequent reload/recovery without rebuilding the TUN. Existing streams drain naturally. |
| `GetStatus` | `GetStatus() string` | JSON of `core.Status` | See schema below. Safe to call at any time. Reads `listener.GetPorts()`, `listener.GetTunConf()` + `statistic.DefaultManager`. |
| `GetTraffic` | `GetTraffic() string` | JSON of `core.Traffic` | Sourced from `statistic.DefaultManager.Now/Total`; `synthetic:false`. |
| `GetVersion` | `GetVersion() string` | JSON `{nozeltCore, mihomo}` | Cheap, pure. |
| `SetLogger` | `SetLogger(l Logger)` | — | Pass `nil` to detach. Callback is invoked from arbitrary Go goroutines. Mihomo's internal log stream is forwarded through this same callback. |
| `ParseProxyLink` | `ParseProxyLink(link string) string` | JSON `{ok, proxy}` / `{ok:false, error}` | Parses one share link via `convert.ConvertsV2Ray`. Recover-wrapped, 64 KiB maximum, pure/no network. |
| `ParseSubscription` | `ParseSubscription(content string) string` | JSON `{ok, proxies, count}` / `{ok:false, error}` | Parses already-downloaded Clash YAML/base64/plain links. 16 MiB and 4096-proxy limits; host does the HTTP GET. |
| `TestProxyDelays` | `TestProxyDelays(configYAML, namesJSON, testURL string, timeoutMs int) string` | JSON delay envelope | Requires an active protected VPN and HTTPS, uses at most eight workers, and closes temporary adapters/providers. Stop/Reload/Recover cancels registered probes before changing global network state. |
| `TestProxyDelaysOffline` | `TestProxyDelaysOffline(configYAML, namesJSON, testURL string, timeoutMs int) string` | JSON delay envelope | Requires both the core and Android socket protector to be stopped. Proxy endpoint DNS must be encrypted; installing the protector or starting the VPN cancels and drains all direct probes before the network mode changes. |

### Parsing bindings (iteration 4)

Link and subscription parsing is **fully delegated to mihomo's
`common/convert`** — no hand-rolled parser on the host side, because
share-link formats vary per panel (Remnawave, Marzban, 3x-ui, …), especially
Reality/XHTTP, and mihomo already normalises them.

`ParseProxyLink` returns:

```json
{ "ok": true, "proxy": { "name": "...", "type": "vless", "server": "...",
                         "port": "443", "reality-opts": {...}, ... } }
```

`ParseSubscription` returns `{ "ok": true, "proxies": [ {...}, ... ],
"count": N }`. Both return `{ "ok": false, "error": "..." }` on failure.
Third-party parser errors and panic payloads are collapsed to deterministic
messages because they may quote a complete credential-bearing link. The same
rule applies to config parsing and latency transport errors: callers receive a
category, never an endpoint or raw configuration fragment.

**Native protocols** (`convert.ConvertsV2Ray`): vless (+reality: `pbk`→
public-key, `sid`→short-id, `fp`→client-fingerprint, `sni`→servername;
+flow xtls-rprx-vision; +xhttp with the xray `extra` mapping; +ws/grpc/h2/
http), vmess (v2rayN base64 + Xray VMessAEAD), trojan, ss (+obfs/v2ray-plugin),
ssr, tuic (v4/v5), hysteria, hysteria2/hy2 (including Gecko obfuscation),
anytls, mieru, socks5/http(s). Gecko requires mihomo v1.19.26 or newer;
Nozelt pins v1.19.32 and protects the share-link/config path with a unit test.

**NOT parsed** (unsupported schemes — surface as `ok:false`): `wireguard`,
`naive`, `ssh`. Reality `spx` (spider-x) is ignored (server-side only).

Subscription format detection: a `proxies:`/`proxy-providers:` line ⇒ Clash
YAML (parsed via `config.UnmarshalRawConfig`, checked first so a stray
`https://` inside a YAML is not mistaken for an http proxy); otherwise the
content is fed to `convert.ConvertsV2Ray`, which base64-decodes internally.

### Logger interface

```go
type Logger interface {
    Log(level string, message string)
}
```

`level` is one of `"debug" | "info" | "warning" | "error"` (see
`logger.Level*` constants). Mihomo's own log levels (DEBUG/INFO/WARNING/
ERROR/SILENT) are mapped 1:1 to these strings; SILENT events are dropped.

### Status JSON schema

```json
{
  "running": true,
  "startedAtUnix": 1731839280,
  "uptimeSeconds": 1234,
  "mihomoVersion": "1.19.32",
  "nozeltCoreVersion": "0.5.0-dev",
  "mode": "rule",
  "listeners": {
    "mixedPort":  0,
    "httpPort":   0,
    "socksPort":  0,
    "redirPort":  0,
    "tproxyPort": 0
  },
  "connectionsCount": 0,
  "tun": {
    "enabled": true,
    "stack":   "gvisor",
    "fd":      42
  },
  "openFileDescriptors": 162,
  "goRoutines": 54,
  "socketProtection": true,
  "protectedSockets": 18,
  "protectionFailures": 0
}
```

`mode` is one of `"rule" | "global" | "direct" | ""` (empty when stopped or
unknown). Each listener value is `0` when that inbound type is disabled in
the active config. `connectionsCount` is the size of mihomo's live
connection tracker map. `tun` (iteration 3) reflects mihomo's live
`listener.GetTunConf()`: `enabled` is true only when the sing-tun listener
actually came up, `stack` is the lowercase stack name (`"gvisor" | "system"
| "mixed"`), and `fd` is the adopted Android descriptor (`0` when down).
The protection counters are aggregate only: the core does not retain socket
descriptors, destinations, profile names, or credentials. Android diagnostics
use these fields together with the listener/FD/goroutine counts.

Field naming is camelCase to stay compatible with the Dart side's
`json_serializable`-generated parsers. Adding new fields is non-breaking;
renaming or removing existing fields is.

### Traffic JSON schema

```json
{
  "uploadBytes": 0,
  "downloadBytes": 0,
  "uploadSpeedBps": 0,
  "downloadSpeedBps": 0,
  "activeConnections": 0,
  "synthetic": false
}
```

`synthetic` is always `false` since iteration 2 — Go has real numbers from
`statistic.DefaultManager` now. The Kotlin TrafficStreamHandler used to
fabricate values when this flag was missing or `true`; that path is gone
but the field stays in the schema as a guard against future regressions.

## 5. Data flow: config from Flutter to mihomo

1. **Flutter UI** renders a JSON document (valid YAML) from validated settings,
   the selected normalized proxy node, and routing rules. The Android host
   encrypts it in Keystore-backed runtime storage before starting VpnService.
2. **Kotlin VpnService** decrypts the active document in-process and calls
   `binding.Binding.start(config)` (or `reloadConfig(config)`) from the
   gomobile-generated JNI glue.
3. **`binding/binding.go`** forwards to `core.Start` / `core.ReloadConfig`
   verbatim — no transformation.
4. **`core/config.go::parseConfig`** rejects empty input, then calls
   `mihomo/config.Parse([]byte(yaml))`. mihomo's own diagnostics are
   wrapped with `mihomo parse:` so they're distinguishable from our
   validation failures.
5. **`core/core.go::applyConfig`** calls `executor.ApplyConfig(cfg, true)`.
   mihomo mutates its global state: inbounds, outbounds, rules, DNS,
   sniffer, hosts trie.
6. **`core/core.go::verifyListeners`** compares each non-zero port in
   `cfg.General` (mixed/http/socks/redir/tproxy) with the actual values
   from `listener.GetPorts()`. A mismatch — typically because the port is
   already in use — surfaces as a typed error from `Start()` even though
   `ApplyConfig` itself never returns errors.
7. **mihomo** is ready to serve packets from the TUN. Nozelt's Android config
   requests no HTTP/SOCKS/Mixed/Redir/TProxy listener; all reported ports must
   therefore remain zero.

### 5a. TUN bring-up and the fd (iteration 3)

Real device-wide routing goes through a TUN interface whose file descriptor
is created on the **Kotlin** side and adopted by mihomo:

1. **Kotlin** calls `VpnService.Builder.establish()` → `ParcelFileDescriptor`,
   retains it as a fail-closed keeper, then duplicates + `detachFd()` to get
   the raw int fd for Go. It first installs a
   `SocketProtector` backed by `VpnService.protect`, then calls
   `binding.Binding.setTunFd(fd)` **before** Start.
2. **`core.SetSocketProtector`** installs mihomo's default raw-socket hook;
   TCP and UDP/QUIC/HY2 transports cannot connect unless Android accepts
   protection. `core.SetTunFd` stores the TUN fd under `current.mu`.
3. The YAML from Kotlin has `tun.enable: true` (+ stack, mtu, `dns-hijack:
   [any:53]`, `auto-route: false`) but **no** `file-descriptor` — Kotlin does
   not own the config text.
4. **`core.applyConfig`** stamps `cfg.General.Tun.FileDescriptor =
   current.tunFd` just before `executor.ApplyConfig`. A TUN-enabled config
   with no fd is a hard error.
5. **`executor.ApplyConfig`** → `updateListeners` → `listener.ReCreateTun` →
   `sing_tun.New`. Because `FileDescriptor > 0`, sing-tun wraps the existing
   fd (`os.NewFile`) instead of opening `/dev/net/tun`, and skips all route /
   address setup (Android's VpnService owns routing).
6. **`core.applyConfig`** then reads `listener.GetTunConf().Enable` — true iff
   the TUN listener actually came up — and returns a typed error otherwise.
7. Packets from the device now flow: **app → Android TUN fd → sing-tun →
   mihomo tunnel → rules → DIRECT/proxy**. DNS entering the TUN on port 53 is
   hijacked (`any:53`) and answered from the fake-ip pool so domain rules
   match before the real connection is made.

Logging flows the other way and runs continuously:

- A goroutine spawned in `core.init()` subscribes to `mihomo/log.Subscribe()`.
- Every `log.Event` is mapped to one of our four level strings and pushed
  through `logger.Emit`. If a host `Logger` is installed (via
  `binding.SetLogger`), it sees mihomo's internal log lines; the Android host
  applies redaction and enables logcat only for debuggable builds.
- The subscription is intentionally not unsubscribed — it lives for the
  process. Memory growth is bounded by the host's drain rate.

## 6. Lifecycle of mihomo inside our wrapper

| Step | What we do | What mihomo sees |
|------|------------|------------------|
| `SetSocketProtector(p)` | retain Android callback; install `DefaultSocketHook` | every new transport socket is protected before connect/bind |
| `SetTunFd(fd)` | store fd under lock | nothing yet |
| `Start(yaml)` | parseConfig → applyConfig (inject fd, verifyListeners, verifyTun) → record state | `executor.ApplyConfig(cfg, force=true)` — first apply, fresh listeners incl. TUN on the fd |
| `ReloadConfig(yaml)` | fingerprint proxy sections; reuse live adapters for rules-only updates, otherwise apply and close the old adapters | listeners with the same address are reused; routing edits do not allocate another HY2/QUIC/TLS client set |
| `RecoverNetwork()` | reparse active config, close tracked connections and previous proxy adapters, reapply with same fd, restore selector choices | stale TCP/QUIC/DNS state is dropped; apps reconnect through the new Android underlay on the same chosen node |
| `SelectProxy(group, proxy)` | validate and call `Set` under the lifecycle write lock, then remember the choice in memory | new connections use the selected adapter; reload/recovery cannot silently reset it |
| `StopForRestart()` | perform the complete teardown but retain the in-memory FakeDNS host mapper | a cached synthetic answer remains routable across the keeper-backed replacement; the next DNS enhancer clones it and no mapping is persisted to disk |
| `Stop()` | close trackers; `executor.Shutdown()`; reset stale `LastTunConf`; close outbound adapters/proxy+rule providers; clear DNS/fake-IP memory and global tunnel maps; explicit `listener.ReCreate*(0, tunnel.Tunnel)`; clear fd | TUN/fd, transports, provider fetch/health tasks, cached browsing mappings, and every inbound are gone before return; a reused Android fd cannot be mistaken for the closed listener |
| process exit | nothing extra | n/a |

`core.shutdownSlowWarning = 10s` is diagnostic, not a timeout. Stop waits for
the process-global listener cleanup to finish. Returning while an abandoned
shutdown goroutine is still active would be unsafe: it could later close the
TUN/listeners belonging to a new session.

While running, a 30-second resource watchdog checks `/proc/self/fd`. A normal
mobile session stays below a few hundred descriptors; at 1024 the guard calls
`RecoverNetwork` to cut off a retry/FD storm well before Android's approximate
32K process limit. `Stop` cancels the watchdog.

### 6a. TUN fd ownership — distinct descriptors, no double close

`VpnService` retains the original `ParcelFileDescriptor` as a fail-closed
keeper and passes Go a detached **duplicate**. Once Kotlin calls
`SetTunFd(fd)` with `fd > 0`, Go solely owns that duplicate; Kotlin never
closes it. The service solely owns the original and never passes its numeric
fd to Go. Keeping it open preserves Android's VPN route as a black hole while
the packet engine is restarting. Concretely:

- **Success** (`Start` returns nil): mihomo's sing-tun listener wraps the fd
  and closes it during `Stop` (`executor.Shutdown → listener.Cleanup →
  closeTunListener → NativeTun.Close`). `core` keeps `current.tunFd` only as
  a reference (for status and TUN-preserving reloads) and clears it in `Stop`.
- **Failure before sing-tun adopts it** (parse error, already-running, TUN
  failed to start): sing-tun never took the fd, so `core` closes the raw fd
  itself via `os.NewFile(fd).Close()` (`closeTunFdRawLocked`). If executor had
  already published other candidate state, the failed-start rollback also
  shuts listeners and clears adapters, rules, providers and resolver objects.
- **Failure after sing-tun adopts it** (a later check like `verifyListeners`
  fails while the TUN is up): the failed-start rollback calls
  `shutdownMihomo`, which closes the fd via sing-tun.

Either way the Go duplicate is closed **exactly once**. The only case where
Kotlin closes that duplicate is if `setTunFd` itself throws (Go never recorded
it) — it then does `ParcelFileDescriptor.adoptFd(fd).close()`. Independently,
Kotlin swaps/closes its keeper after a replacement starts and closes it on an
explicit disconnect, revoked permission, terminal start failure, or service
destruction.

`onRevoke` (system revoked the VPN) routes through `Stop`, so both descriptors
are closed on that path too.

## 7. Build

- **Go toolchain 1.26.8** (selected by `go.mod`; language version remains
  `go 1.26.0` for dependency compatibility).

  Add `android/amd64` later only if needed (emulator targets).

  Android app with Nozelt's default gVisor TUN stack. `cmfa` disables
  mihomo's privileged `/data/system/packages.xml` resolver; `with_gvisor`
  includes the userspace stack. Nozelt applies per-app routing through

## 8. Known limitations and TODO

**Still on the Android / Kotlin side (not this module):**

- Ownership of the `VpnService`, the route table, `addDnsServer`, and per-app
  split-tunnel rules. `nozelt-core` only serves the packet engine on the fd
  Kotlin hands it via `SetTunFd`.
- Subscription **downloading** (HTTP GET). `nozelt-core` only *parses*
  already-fetched content (`ParseSubscription`); the host does the network.
- Profile management / persistence, config assembly (the host builds the JSON
  config and passes it to `Start`).
- System-level VPN permission UX.

**Deferred features (later iterations):**

- Share-link protocols mihomo's convert does not handle: `wireguard`, `naive`,
  `ssh` (return `ok:false`).
- GEO-based rule sets still need a signed/versioned geodata provisioning path;
  host-side exact/suffix/keyword/CIDR rules are implemented.
- Scheduled subscription refresh is host-driven (Dart), not in-core.
- Hot-reload that changes TUN parameters. Changing stack/MTU currently needs
  a reconnect: closing the TUN listener closes the fd, and it cannot be
  reopened on the same (now-closed) fd — a fresh `establish()` + `SetTunFd`
  is required. Reloads that keep the TUN unchanged (rules/proxies only) are
  fine.
- Encrypted config-at-rest is an Android host responsibility and is implemented
  there with Keystore AES-GCM; this Go module only sees plaintext in memory.
- More unit tests — connection-tracker-based Traffic assertions and an Android
  instrumented protect(fd) integration test.
- CI to build `.aar` on every push.

**Known caveats:**

- mihomo uses process-global state (hub, tunnel, statistic). The wrapper
  reflects that with a package-level singleton in `core`. Do not try to
  instantiate multiple mihomo instances per process — it will not work.
- `executor.ApplyConfig` itself never returns errors. Anything that goes
  wrong at apply time (a port that won't bind, a malformed DNS rule) is
  visible only in the log stream. We catch the most common case — closed
  listeners — with `verifyListeners`; the rest is the host's
  responsibility to surface in the UI by watching the log stream.
- `executor.Shutdown` in mihomo only tears down the TUN listener. We
  compensate by clearing its retained TUN comparison config and closing
  HTTP/SOCKS/Mixed/Redir/TProxy listeners via
  explicit `listener.ReCreate*(0, …)` calls.
  The TUN reset is required because Android frequently reuses the same integer
  for the next duplicated fd; without it, upstream `ReCreateTun` can report
  the stale enabled config while no listener exists. If mihomo upstream
  changes what Shutdown covers, revisit `core.shutdownMihomo`.
- The mihomo log subscription is a long-lived goroutine started from
  `core.init()`. It is never closed. This is by design: a single
  subscription has bounded memory cost and unsubscribing complicates the
  lifecycle for no benefit (the Logger may still want to capture events
  emitted after Stop).
- `go.mod` module path is `github.com/nozelt/nozelt-core`. Change via
  `go mod edit -module` if a different org/path is needed.
